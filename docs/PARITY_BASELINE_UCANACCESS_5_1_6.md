# Parity baseline: UCanAccess 5.1.6

This is the compatibility baseline for the .NET provider. It deliberately
separates the Java reference behaviour from the ADO.NET-specific public API.
An item may be marked **Supported** in the compatibility matrix only when it
has a focused .NET test and the appropriate reference evidence below.

## Pinned reference stack

| Component | Version | Role |
|---|---:|---|
| Java UCanAccess | 5.1.6 | SQL/JDBC behavioural reference |
| Jackcess | 5.1.5 | Access file-format reader/writer reference |
| HSQLDB | 2.7.4 | Runtime dependency of the Java SQL oracle |
| Java | 11 or newer | Oracle execution environment |

The versions are pinned in
[`tools/JavaOracle/prepare.ps1`](../tools/JavaOracle/prepare.ps1). Do not
silently upgrade one of them while refreshing expected results: upgrade the
baseline document, dependencies and affected fixtures in the same change.

## Evidence map

| Surface | Reference input/output | .NET evidence | Required change discipline |
|---|---|---|---|
| File structure and values | `tests/fixtures/oracle/*.json`, generated by Jackcess `DbDump` | File differential tests | Regenerate only when a fixture or pinned Jackcess behaviour changes. |
| SQL SELECT semantics | `tests/fixtures/sql/*.sql` and `*.java.json`, generated by Java `SqlDump` | SQL parity corpus | Add an original-Java result for a new broadly supported SQL form. |
| File writes and DDL | Java `DdlRunner`/`DbDump` read-back | DDL and write tests | Verify that the produced MDB/ACCDB remains readable by Jackcess. |
| ADO.NET contracts | No JDBC one-to-one equivalent | Focused provider tests | State the .NET semantic explicitly in `COMPATIBILITY_MATRIX.md`. |
| Connection options | Java UCanAccess option spelling and intent | Parser and integration tests | Map aliases only where their meaning is well-defined for the SQLite mirror. |

Current focused compatibility tests outside the historical SQL corpus include:

- rejection of `TOP n PERCENT`, which UCanAccess 5.1.6 reports as a syntax error;
- `SELECT @@IDENTITY` after an Access AutoNumber insert;
- `ALTER TABLE ... RENAME TO` plus relationship-catalog reference updates;
- `ALTER TABLE ADD [CONSTRAINT] PRIMARY KEY` staged file mutation, with the
  upstream-rejected `DROP PRIMARY KEY` and `DROP CONSTRAINT` forms rejected;
- `keepMirror=<path>`, `memory`, `immediatelyReleaseResources`,
  `preventReloading` and `sysSchema` mapping.

## Refresh procedure

Run the following from the repository root when intentionally refreshing the
Java baseline:

```powershell
pwsh tools/JavaOracle/run.ps1
dotnet test UCanAccess.slnx
```

The script downloads the pinned jars into the system temporary directory and
updates oracle files under `tests/fixtures`. Review every changed JSON file;
an oracle refresh is evidence of changed reference behaviour, not an automatic
approval to alter provider expectations.

## Explicit non-parity areas

The Java stack is JDBC/HSQLDB based whereas this provider is ADO.NET/SQLite
mirror based. Connection pooling, updatable JDBC result sets and HSQLDB-specific
configuration are therefore not copied as false-compatible options. Encrypted
containers, saved-query write lifecycle and foreign-key DDL remain partial or
unsupported until they receive their own format-level writer and differential
fixtures.
